# Security Architecture Plan — Pastry Management System

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Define the security design every later module plan must follow, and specify the security primitives the Foundation plan builds first. Security is designed in from the start, not added afterwards.

**Architecture:** Defense in depth with **three independent tenant-isolation layers**: (1) a service-layer permission check, (2) a Prisma extension that forces `organizationId` scoping, and (3) Postgres Row-Level Security under a least-privilege database role. Invite-only accounts, mandatory TOTP for **every** user, short sessions, an append-only audit log, private image storage, strict HTTP headers/CSP, rate limiting, and a security test suite that runs in CI.

**Tech Stack additions:** Better Auth plugins `twoFactor` + `haveIBeenPwned` + `organization` (dynamic AC); `resend` (invite/reset emails); `files-sdk` + `@aws-sdk/client-s3` + `@aws-sdk/s3-request-presigner` + `@aws-sdk/s3-presigned-post` (Neon buckets); `sharp` + `file-type` (image validation/re-encoding); `@sentry/nextjs` (PII-scrubbed error monitoring); `eslint-plugin-security`; `gitleaks` (CI).

## Controls

### A. Identity & authentication (Better Auth, `src/server/auth/auth.ts`)

- **A1 Invite-only.** Set `emailAndPassword: { enabled: true, disableSignUp: true }`. Accounts are created only by (a) `prisma/seed.ts` for the first owner, reading `SEED_OWNER_EMAIL`, or (b) accepting an organization invitation. Invitations expire after 48h (`invitationExpiresIn`), and accepting one requires the invited email address.
- **A2 Passwords.** Minimum 12 characters, maximum 128 (`minPasswordLength`/`maxPasswordLength`). The `haveIBeenPwned` plugin rejects known-breached passwords. Better Auth's default scrypt hashing stays. `revokeSessionsOnPasswordReset: true`. Reset tokens are single-use and expire in 30 min.
- **A3 Mandatory TOTP for everyone.** Use the `twoFactor` plugin with backup codes. The plugin enforces TOTP at sign-in only once a user has enrolled, so **we enforce enrollment ourselves**:
  - The API wrapper (`withAuth`, below) rejects any session whose `user.twoFactorEnabled !== true` with `403 TWO_FACTOR_REQUIRED`. The only exceptions are the enrollment endpoints and `/api/auth/*`.
  - `src/proxy.ts` redirects such users to `/setup-2fa`.
  - Invitation acceptance leads straight into enrollment.
  - "Trust this device" is allowed for **7 days max**. It skips the TOTP prompt, never the password.
- **A4 Email ownership.** An invitation proves email ownership. An email change requires re-verification of the new address, plus a notification to the old one.
- **A5 Sessions.**
  - Cookies are httpOnly, `Secure` (`advanced.useSecureCookies: true`), `SameSite=Lax` and use the `__Secure-` prefix.
  - Lifetimes: `expiresIn: 12h` (one shift), `updateAge: 1h`, `freshAge: 10m`. Sensitive actions require a *fresh* session (password/TOTP re-entry): changing roles or members, disabling 2FA, changing prices in bulk, exporting reports.
  - Removing a member or changing their role revokes **all** of that user's sessions.
  - Users can list and revoke their own sessions in Settings.
- **A6 Role-grant ceiling (closes the escalation gap).** A `hooks.before` in the auth config runs on `/organization/create-role`, `/organization/update-role`, `/organization/update-member-role` and `/organization/invite-member`. It uses `assertCanGrant(caller, requested)` from `src/server/auth/grant-ceiling.ts` and rejects the request if:
  - the requested permission set is not a subset of the caller's own effective permissions;
  - the target role is `owner` and the caller is not an owner;
  - the caller targets their own membership.

  In addition, the built-in `admin` role loses `ac:create|update|delete` by default. This is not owner-exclusive: an owner may delegate role-definition power to a trusted non-admin by granting a custom role that includes `ac:create`/`ac:update`, and `assertCanGrant` caps that delegate at their own permission ceiling — they can never define a role broader than what they hold. Admins can still assign existing roles, but only within their ceiling.
- **A7 Brute-force protection.** Better Auth `rateLimit: { enabled: true, storage: "database" }` (serverless-safe: rate-limit counters kept in memory would reset per instance), with `customRules`:
  - `/sign-in/email`: 5 per 60s
  - `/two-factor/*`: 5 per 60s
  - `/forget-password`: 3 per 300s
  - `/organization/invite-member`: 20 per 3600s

  In addition, a Vercel Firewall rate-limit rule on `/api/auth/*` blocks by IP before requests reach the app.
- **A8 Trusted origins.** Set `trustedOrigins` to the exact production and preview URLs from env, with localhost **only** when `NODE_ENV !== "production"`. This blocks CSRF and open redirects on the auth routes.

### B. Authorization (deny by default)

- **B1 One gate for every API route.** Every `src/app/api/v1/**/route.ts` handler is wrapped as `export const POST = withAuth({ permission: { product: ["create"] } }, handler)` (`src/server/http/with-auth.ts`). `withAuth`:
  1. loads the session (401 if none);
  2. requires `twoFactorEnabled` (403);
  3. requires an active organization (403);
  4. checks `auth.api.hasPermission` for the declared permission (403);
  5. resolves and validates the branch (B3);
  6. checks `Origin` on mutations (E2);
  7. builds `ctx`.

  **A route without `withAuth` fails a lint/test check.** This is the Task 6 route inventory test, which asserts every exported handler is a `withAuth` result.
- **B2 Fixed permission vocabulary.** The statement in `src/server/auth/permissions.ts` is code-owned. Custom roles can only combine these resources and actions:
  - `product`: create, read, update, delete, price
  - `category`: create, read, update, delete
  - `ingredient`: create, read, update, delete
  - `inventory`: read, adjust, transfer
  - `supplier`: create, read, update, delete
  - `recipe`: create, read, update, delete
  - `production`: create, read, cancel
  - `order`: create, read, void, refund, discount
  - `report`: read, export
  - `branch`: create, update, delete
  - `audit`: read
  - plus Better Auth's `organization`, `member`, `invitation`, `team` and `ac`.
- **B3 Branch scoping from membership.** The branch the client sends (header `x-branch-id`) is **never trusted**. `withAuth` checks that the user is a member of that team (branch) in the active organization, unless they hold an org-wide role (owner/admin), and puts the verified `branchId` in `ctx`. The branch selected in Zustand is only a UI hint.
- **B4 `ctx` is the only source of tenant ids.** Services and repositories take `ctx: { userId, organizationId, branchId }`. They never read `organizationId`/`branchId` from the request body or params. Permission checks are not cached on `ctx` — services call `requirePermission(ctx, {...})` per action (see Task 4), so there's no separate, staleness-prone `permissions` field to keep in sync.
- **B5 Server-side authority.** The UI hides buttons the user lacks permissions for (for convenience only). Every server action re-checks. Prices, totals, discounts and stock changes are **computed on the server**; client-sent totals are ignored.

### C. Tenant isolation in the data layer (defense in depth)

- **C1 Prisma tenant extension** (`src/server/db.ts`). A `$extends` query hook applies to every tenant model (all models with `organizationId`):
  - it injects `where.organizationId = ctx.organizationId` into find, update and delete operations, and sets it on create;
  - it **throws** if called without a tenant context.

  Repositories use `db.forTenant(ctx)`. Only the auth adapter and the seed script use the raw client.
- **C2 Postgres RLS + least-privilege role** (migration `prisma/migrations/*_rls`).
  - Create a role `app_user` without ownership or DDL rights. The runtime `DATABASE_URL` uses `app_user`; migrations keep using the owner via `DATABASE_URL_UNPOOLED`.
  - Enable and **force** RLS on every tenant table, with the policy `organization_id = current_setting('app.org_id')::text`.
  - `db.forTenant(ctx)` wraps each operation in a transaction that first runs `select set_config('app.org_id', $1, true)`. The setting is transaction-local, which is safe with pooled connections.
  - Even a repository bug that forgets a filter then returns **zero rows** instead of another tenant's data.
  - Better Auth tables (`user`, `session`, …) are excluded from RLS and accessed only through the auth adapter.
- **C3 Non-guessable ids.** Use `cuid2`/UUID primary keys everywhere; there are no sequential ids in URLs.

### D. Input validation & output encoding

- **D1 Zod on every input.** Validate body, query and params with `.strict()` schemas (`features/*/schemas.ts`). Unknown keys are rejected, which also blocks mass assignment of `organizationId`, `role` or `price`. Validation failures return 400 with field errors only.
- **D2 No raw SQL string building.** An ESLint `no-restricted-properties` rule bans `$queryRawUnsafe`/`$executeRawUnsafe`. Only tagged `$queryRaw` is allowed.
- **D3 Explicit output DTOs.** Repositories use explicit `select`. Hashes, tokens and TOTP secrets are never returned. A shared `toXxxDTO` exists per feature.
- **D4 XSS.** React escaping everywhere. ESLint bans `dangerouslySetInnerHTML`. User-supplied SVG is never rendered (see F2).
- **D5 Money and quantities.** Store money as integer centavos (`Int`) and quantities as `Decimal`. Validate ranges (no negative prices; discounts ≤ line total).

### E. HTTP / browser hardening

- **E1 Security headers**, set in `src/proxy.ts` (per-request CSP nonce) plus `next.config.ts` `headers()`:
  - `Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-{n}' 'strict-dynamic'; style-src 'self' 'nonce-{n}'; img-src 'self' data: blob: <neon-storage-origin>; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'`. MUI/Emotion receives the nonce via `AppRouterCacheProvider options={{ nonce }}`.
  - `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=()`
  - `Cross-Origin-Opener-Policy: same-origin`
- **E2 CSRF for our API.** Besides `SameSite=Lax` cookies, `withAuth` rejects non-GET requests whose `Origin` is not in the trusted list, and requires `Content-Type: application/json`. No CORS headers are sent (same origin only).
- **E3 Errors.** An `AppError` hierarchy (`src/server/errors.ts`) maps to status codes. Unknown errors return `500 {"error":"INTERNAL","requestId"}` with no stack trace, message or Prisma detail. The full error goes to Sentry with PII scrubbing.
- **E4 POS kiosk hygiene.** The POS screen auto-locks after 5 min idle (configurable per org) and requires a re-sign-in. "Sign out" clears the TanStack Query cache and the Zustand stores, so the next cashier sees nothing from the previous one.

### F. File uploads (Neon buckets)

- **F1 Private bucket only.** In `neon.ts`, declare `buckets: { "product-images": {} }` (private). Images are served through **presigned GET URLs** (5 min expiry) issued only after the same `withAuth` read permission. The bucket credentials (`AWS_*` env) are server-only.
- **F2 Validate, then re-encode.** Upload goes through our API, not directly to S3:
  - Max 5 MB.
  - Check magic bytes with `file-type`: only JPEG, PNG or WebP (no SVG, no GIF).
  - `sharp` re-encodes to WebP with a max dimension of 2000px, which strips EXIF/GPS metadata and neutralizes polyglot files.
- **F3 Keys.** `org/<orgId>/products/<cuid>.webp`, server-generated, so the user never controls the path. The key is stored in the Product row. Old keys are deleted on replacement.
- **F4 Tenant check on read.** A presign request goes through the repository with `forTenant(ctx)`, so a key from another organization is never signed.

### G. Business integrity & audit (insider fraud)

- **G1 Append-only `AuditLog`** (`organizationId, branchId, actorId, action, entity, entityId, before JSONB, after JSONB, ip, userAgent, requestId, createdAt`).
  - `app_user` has INSERT and SELECT only; `REVOKE UPDATE, DELETE`.
  - Written in the **same transaction** as the change it records.
  - Logged actions: sign-in (success and failure), 2FA changes, member/role/invite changes, price changes, stock adjustments/transfers, production cancels, order void/refund/discount, report exports, and branch create/delete.
- **G2 Inventory as a ledger.** Stock changes are immutable `StockMovement` rows (type, qty, reason, actor), and current stock is derived from them. Adjustments require a reason code. There are no silent overwrites.
- **G3 Sensitive POS actions.** Void, refund and discount above an org-set threshold each need their own permission (`order:void`, `order:refund`, `order:discount`). A manager override (PIN plus a permission check on the manager's account) is audited with both actor ids. There are no hard deletes of orders; only status transitions.
- **G4 Soft delete** for products, categories, suppliers and recipes (`deletedAt`), so historical orders and reports stay intact.

### H. Secrets & configuration

- **H1 `src/env.ts`.** A Zod-validated, `server-only` env module. The app fails fast at boot if a variable is missing or malformed. Only `NEXT_PUBLIC_*` values may reach the client (currently none are needed).
- **H2 Vercel env per environment.** Set secrets as Production/Preview/Development variables (encrypted at rest). Preview deployments use a **Neon preview branch**, never production. Sensitive-data branches for dev are **schema-only** (see the `neon-postgres-branches` skill).
- **H3 Local secrets.** `.env` stays gitignored (already true). A `gitleaks` scan runs in CI. Turn on GitHub secret scanning and push protection in the repo settings (the user does this in GitHub).
- **H4 Rotation runbook** (`docs/security/runbook.md`): how to rotate `BETTER_AUTH_SECRET` (this signs out everyone), Neon role passwords (`neon roles reset-password`), the bucket credentials and the Resend key.
- **H5 Action item from the Neon setup.** `neon mcp -y` minted an account-wide API key (id `3375142`) and saved it in the Copilot, VS Code and Windsurf configs. Recommend revoking it (`neon api-keys revoke 3375142`), re-running `neon mcp --oauth -a claude-code`, and deleting the Neon entries from the other tools' configs.

### I. Abuse & availability

- **I1 Vercel Firewall.** Enable the managed ruleset and bot protection. Add rate-limit rules: `/api/auth/*` 30/min per IP; `/api/v1/*` 300/min per IP; `/api/v1/**/upload` 10/min.
- **I2 In-app limits for expensive endpoints.** Reports and exports get a per-user DB-backed limit (reusing the `rateLimit` table) and a maximum date range of 366 days. List endpoints are always paginated (max `limit=100`).

### J. Supply chain

- **J1 Dependencies.** Commit `package-lock.json`. CI runs `npm ci` and `npm audit --audit-level=high`, gated with an allowlist file for the known dev-only Prisma CLI findings. Enable Dependabot security updates.
- **J2 Install scripts.** Keep npm's `allowScripts` blocking and approve explicitly only `@prisma/engines`, `prisma`, `esbuild`, `sharp` and `unrs-resolver`.
- **J3 Static analysis.** `eslint-plugin-security` plus the D2/D4 rules. GitHub CodeQL runs on the repo (user enables it). Run `/security-review` before each release.

### K. Data protection & recovery

- **K1 Transport.** The Neon URLs already enforce `sslmode=require&channel_binding=require`. Neon encrypts data at rest.
- **K2 Backups.** Set Neon instant-restore (PITR) retention to the plan maximum. Mark the `production` branch as **protected**. Run a restore drill before launch.
- **K3 Migration safety.** Test every migration on a Neon branch forked from production before `migrate deploy`. There are no destructive migrations without a backup branch.
- **K4 Minimal PII.** Staff name and email only. Customer name and phone on orders are optional. Only the owner can export data, and exports are audited.

### L. Monitoring

- **L1 Sentry.** Use `beforeSend` to scrub emails, cookies and Authorization headers.
- **L2 Security alerts.** Use the audit log plus a daily digest query for: more than 10 failed sign-ins per account per hour, role changes, 2FA disabled, voids above threshold. Wire these into email via Resend in the Reports plan.
- **L3 Vercel log drains** stay on (a 30-day minimum is recommended).

```ts
// src/server/errors.ts
import "server-only";
export class AppError extends Error {
  constructor(public code: string, public status: number, public details?: unknown) { super(code); }
}
export class UnauthorizedError extends AppError { constructor() { super("UNAUTHORIZED", 401); } }
export class ForbiddenError extends AppError { constructor(code = "FORBIDDEN") { super(code, 403); } }
export class NotFoundError extends AppError { constructor() { super("NOT_FOUND", 404); } }
export class ValidationError extends AppError { constructor(details: unknown) { super("VALIDATION", 400, details); } }

export function toErrorResponse(err: unknown, requestId: string): Response {
  if (err instanceof AppError) {
    return Response.json({ error: err.code, details: err.details, requestId }, { status: err.status });
  }
  return Response.json({ error: "INTERNAL", requestId }, { status: 500 });
}
```

- [ ] Test: `assertCanGrant({product:["read"]}, {product:["read","price"]})` throws `ForbiddenError("GRANT_EXCEEDS_OWN")`. `assertCanGrant(ownerPerms, {...}, { targetRole: "owner", callerIsOwner: false })` throws. The self-target case throws. A subset passes.

```ts
// src/server/auth/grant-ceiling.ts
import "server-only";
import { ForbiddenError } from "@/server/errors";
type Perms = Record<string, readonly string[]>;

export function assertCanGrant(
  caller: Perms,
  requested: Perms,
  opts: { targetRole?: string; callerIsOwner?: boolean; targetUserId?: string; callerUserId?: string } = {},
) {
  if (opts.targetUserId && opts.targetUserId === opts.callerUserId) throw new ForbiddenError("CANNOT_MODIFY_SELF");
  if (opts.targetRole === "owner" && !opts.callerIsOwner) throw new ForbiddenError("OWNER_ONLY");
  for (const [resource, actions] of Object.entries(requested)) {
    const allowed = new Set(caller[resource] ?? []);
    if (actions.some((a) => !allowed.has(a))) throw new ForbiddenError("GRANT_EXCEEDS_OWN");
  }
}
```
